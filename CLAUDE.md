# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Static marketing website for Studio Santé Active, a training studio in Montréal (https://studiosanteactive.com). Plain hand-written HTML, CSS and one small vanilla JS file, deployed by Netlify straight from the GitHub repo (pushing to `master` publishes the live site). There is no build step, package manager, or test suite. All site content is in **French** (`lang="fr-CA"`), so keep new copy in French.

## Running locally

Links and assets use root-absolute paths, so serve the site from the repo root rather than opening files directly:

```sh
python3 -m http.server 8000   # then open http://localhost:8000
```

Internal links must point to the `.html` files (`/equipe.html`; the home page is `/`) so they work on any static server. Only the canonical URLs, `og:url`, JSON-LD and `sitemap.xml` use extensionless URLs (`/equipe`), which Netlify also serves.

Checks (the relaxed html-validate rules are intentional: lowercase doctype, inline styles, muted autoplay hero video):

```sh
npx html-validate@8 --config <(echo '{"extends":["html-validate:recommended"],"rules":{"doctype-style":"off","no-inline-style":"off","tel-non-breaking":"off","no-autoplay":"off"}}') *.html
node --check scripts/site.js
```

## Architecture

- **Mobile first.** Design and check every change at phone width (~390px) before desktop: base CSS is the phone layout, and the navbar only expands at 1200px (`navbar-expand-xl`).
- **One self-contained HTML file per page**: `index` (Accueil: intro, À propos text, events, photo carousel, Google reviews), `equipe` (Équipe d'entraînement: trainers, then therapist collaborators), `entrainement-prive` (à la carte, private 1:1 and semi-private prices), `services-complementaires` (nav label "Autres services": pilates, boxe/powerlifting, online), `ceg` (Cours en groupe: Fliip schedule, class list, prices), `contact`, `faq`, `conditions` (Termes et conditions), `carrieres` (Carrière et stage), plus `404.html`, which Netlify serves for missing URLs. There are no templates or includes, so the `<head>` (including the inline night-mode script), skip link, floating `.contact-popin` CTA (omitted on `contact.html`/`404.html`), `<header class="site-header">` navbar with the night-mode switch, holiday notice bar, and `<footer class="site-footer">` are **duplicated in every page and must stay identical**. A change to any of them (phone, hours, a nav link) must be made in all 10 files.
- **Header**: a slim top strip with the "Ouvert maintenant / Fermé" status (`[data-hours-status]`, hidden until `site.js` fills it), then links (Accueil, Équipe, Entraînement privé, Cours en groupe, Autres services), then `ul.nav-actions` with the calls to action in this order: `.nav-cta` "Réserver votre consultation" (main CTA, to `/contact.html`, bigger and bolder), `.nav-trial` "Cours d'essai gratuit" (Fliip registration), `.nav-client` "Espace client". On phones they stack full width inside the menu; on desktop they form a second row under the links. The floating `.contact-popin` repeats the main CTA (a bottom bar on phones).
- **Footer**: Coordonnées, Horaire, a "Liens" column (including Foire aux questions, Termes et conditions, Carrières) and the map; one column on phones, four on desktop.
- The old `apropos`, `services` and `therapeutes` pages were folded into the pages above in 2026-11; `netlify.toml` 301-redirects their URLs.
- **Per-page SEO** in each `<head>`: unique `<title>` (70 characters max, the validator enforces it), meta description, canonical + `og:url` (extensionless, matching `sitemap.xml`; internal links still use `.html`), `og:image` (the page's banner photo, with its real width/height), and a JSON-LD `@graph`. The current nav link gets `active` + `aria-current="page"`. When adding a page, add it to `sitemap.xml` too.
- **Structured data (JSON-LD)**: every page's graph has the `ExerciseGym` business (`@id` `https://studiosanteactive.com/#studio`), a `WebSite`, and the page node with a breadcrumb. The **full** business node (address, hours, holiday `specialOpeningHoursSpecification`, contact) lives only on `index.html` and `contact.html`; other pages reference it by `@id` and add their own data: trainers as `employee` Persons and therapists as `member` (`equipe`), an `OfferCatalog` of services (`entrainement-prive`, `ceg`), and `FAQPage` questions (`faq`). When page content changes (new trainer, new class, edited FAQ answer), update the matching JSON-LD on that page.
- **Sources**: the studio keeps its holidays in the Google Doc "Congés 2026 + 2027"; the terms page mirrors the Doc "Termes et conditions clients (vers. 2026)".
- **Things that must agree** when hours or holidays change: footer hours (all pages), `HOURS` / `SPECIAL_DAYS` in `scripts/site.js`, `specialOpeningHoursSpecification` in the JSON-LD on `index.html` + `contact.html` (closed days use `opens`/`closes` `00:00`), the static FAQ hours and `[data-holiday-list]` entries, and the FAQ JSON-LD answers.
- **Holiday-season hours** (Christmas Eve, Boxing Day, New Year's Eve...) are set each year in `SPECIAL_DAYS` in `scripts/site.js`, plus the matching JSON-LD and FAQ list entries above. There is no separate seasonal banner to edit: the notice bar under the navbar announces them automatically (up to `NOTICE_MAX_ITEMS` dates, `NOTICE_DAYS_AHEAD` days ahead).
- **`scripts/site.js`** (loaded with `defer` on every page) is purely progressive: pages are complete without it. It fills `[data-current-year]`, the footer open/closed badge `[data-hours-status]`, the `[data-holiday-notice]` bar, and rewrites the FAQ `[data-holiday-list]` to the next 12 months. It shows the homepage video's pause/play button (`[data-video-toggle]`, choice remembered in `localStorage`, hidden under `prefers-reduced-motion`), adds a "Glissez le tableau…" hint under price tables wider than the screen, runs the night-mode switch (`[data-theme-toggle]`, choice saved in `localStorage` as `ssa-theme`), removes homepage events whose `data-event-end` date has passed, opens the `<details>` that a URL hash or table-of-contents link points to (FAQ question, conditions section, trainer bio: `/faq.html#conges`, `/equipe.html#yan-thach`), and wires the "Tout ouvrir / Tout fermer" buttons. It also adds `js-contact-popin` to `<html>` so the floating CTA only shows between the first banner and the footer. All dates are computed in `America/Montreal`. Statutory closures (Jour de l'An, Vendredi saint, Fête nationale, Fête du Canada, Fête du travail, Action de grâce, Noël; the studio is open on Easter Sunday and on the Journée nationale des patriotes) are calculated automatically; one-off closures or reduced hours go in `SPECIAL_DAYS`.
- **Page content** lives in `<main id="contenu">`. Each page has exactly one `<h1>` (the first banner title, or the `.prose` heading on FAQ/Conditions), and heading levels must not skip.
- **CSS**: a single `stylesheets/stylesheet.css`, mobile-first (base = phone, `@media (min-width: 768px)` = tablet, `992px` = desktop). It loads *after* Bootstrap 5.3.3 so it overrides Bootstrap. Bootstrap provides the grid, the collapsing navbar (`navbar-expand-lg`), the homepage carousel, and utilities like `.visually-hidden` and the `[hidden]` reset. Fonts stay Barlow (headings) and Lato (body).
- **Colours and night mode**: every colour is a custom property on `:root` (brand `--ssa-*` values plus role tokens such as `--color-bg`, `--color-text`, `--color-surface`, `--color-accent-text`); never hard-code a colour in a rule. Night mode is `:root[data-theme="dark"]`, which redefines the same tokens, so a new token needs a dark value too. The inline script in each `<head>` sets `data-theme` and Bootstrap's `data-bs-theme` before the page paints (saved choice, else the device setting). Use `--color-accent` for turquoise borders/backgrounds and `--color-accent-text` for turquoise **text** (the bright turquoise fails contrast as text on white). The logo is inverted with a CSS filter at night. The Mailchimp form iframe always stays light.
- **Reusable markup patterns** (copy an existing instance when adding one):
  - Banner: `.banner` > `img.banner-media` + optional `.banner-overlay` with `.banner-title` / `.banner-subtitle`. The first banner image on a page has `fetchpriority="high"`; later ones `loading="lazy"`. The homepage hero is `.banner.banner-hero` with a `<video>`.
  - Offer (`entrainement-prive`, `ceg`): `section.offer` > `.offer-info` (`img.offer-media` + `.offer-text` with the `<h2>`) and `.offer-prices` (price tables + `ul.price-notes`). Add `offer-reverse` to every other offer so the photo and the prices alternate sides on desktop.
  - Price table (its first column stays visible while the plans scroll sideways on phones): `section.price-table-wrap` (unique `aria-label`, `tabindex="0"` so it can scroll sideways on phones) > `table.price-table` with a `<caption>`, a `<thead>` row of plan columns, and one `<tbody>` per group (a `tr.price-group` heading row for "Vos avantages" / "Vos versements", `tr.price-main` for the bi-weekly payment). Cell helpers: `.price-yes` ✓ / `.price-no` ✕ (each followed by a visually-hidden "Inclus" / "Non inclus"), `.price-was` for a crossed-out value, `.price-fav` ♥ for "coup de cœur", `td.price-free` for "Sans frais". Changing a price means editing the table.
  - Group classes (`ceg`): the live schedule is the Fliip iframe (`.schedule-frame`), preceded by `.schedule-hint`. Fliip shows class descriptions only on mouse hover (on touch screens a tap opens sign-up), so the hint has a hover version and a touch version (picked by the `(hover: hover) and (pointer: fine)` media query) that both point to the class list. `ul.class-list` > `article.class-item` (photo, then `.class-body` with `<h3>` and description) uses the same class names and descriptions as Fliip: keep them in sync. Each card ends with `ul.class-tags` (an `aria-hidden` emoji + a text label). The class list comes before the schedule so it's seen first. Yoga Vinyasa has no description in Fliip; the site's text came from an older version of the page.
  - Events (homepage): `article.event` with `data-event-end="YYYY-MM-DD"` inside `.events`; a commented template sits just above the list. The `.events-empty` message shows (by CSS) when no events remain.
  - Reviews (homepage): `.google-rating-score` shows the Google rating (update it by hand); a commented `ul.reviews` template is ready for real Google reviews.
  - Carousel (homepage): Bootstrap `.carousel.gallery`, no autoplay; keep the indicator buttons in step with the slides.
  - Staff: `.trainers` > `article.trainer-card` (with a slug `id` such as `yan-thach` for deep links) > `.trainer-photo` containing an `<img>` (with `width`/`height`) and `.trainer-name`, then `.trainer-role` and a `details.trainer-bio` ("Lire la bio") holding the bio and a `ul.tags` list of specialisations. With JavaScript, `site.js` shows the open bio in a `.trainer-bio-panel` spanning the full row (inserted after the row's last card); without it, the bio opens inside the card. Collaborators (therapists) are in the `#collaborateurs` section: each card is wrapped in `a.trainer-link` to their own site, with a visible `.trainer-link-cta`.
  - FAQ: a `nav.toc` lists every section and question; each question is `<details class="faq-item">` (with an `id`) > `<summary class="faq-question">` + `<div class="faq-answer">`, grouped in `<section>`s with an `<h2>`. The FAQ JSON-LD mirrors these question/answer pairs.
  - Conditions: a `nav.toc`, then each numbered section is a `details.faq-item.faq-section` (with an `id`) whose `<summary>` holds the section's `<h2>`; numbered clauses use `ol.clauses`.
- **External services**: contact form is an embedded Mailchimp iframe (`contact.html`); "Espace client" and "Essai gratuit" go to the Fliip client portal; the reviews button opens the studio's Google Maps listing; Google Analytics tag is in every `<head>`.
- **`netlify.toml`** only holds 301 redirects for legacy URLs (`/apropos`, `/services`, `/therapeutes`, `/nosservices`). Don't add long cache headers for images, which may be replaced in place under the same name.
